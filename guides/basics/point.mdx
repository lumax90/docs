Some labels are not regions, they are locations. A price tag on a shelf, a defect on a weld, a joint on a body, the corner of a court: one coordinate carries the whole meaning. The Point tool drops a class-colored marker exactly where you click, and nothing is faster for high-volume location labeling.

<Info>
Available in image projects. Points share the schema with your other annotation types, so a project can mix points, boxes and polygons per class without any special setup.
</Info>

## Place points

<Steps>
  <Step title="Arm the class">
    Press the class hotkey or click the class in the left panel. Every point you drop takes this class until you switch.
  </Step>
  <Step title="Pick the Point tool">
    Click the point icon in the floating palette.
  </Step>
  <Step title="Click each location">
    One click, one marker. The class chip renders next to each point and every marker becomes an entry in Object Instances.
  </Step>
</Steps>

## Adjust and manage

- **Move a point** with the Select tool by dragging its marker.
- **Reclassify** by selecting the point and pressing another class hotkey.
- **Count coverage** from the class panel: the number next to each class is a live count, which is exactly what you want when guidelines say "mark every price tag".
- **Hide the clutter** with the eye toggles in Object Instances when markers start covering the pixels you still need to read.

## Where points earn their keep

| Scenario | Why points beat boxes |
|---|---|
| Keypoints and landmarks | The model predicts coordinates, not extents |
| Counting tasks (shelf tags, cars in a lot, people in a crowd) | One click per object instead of four corner decisions |
| Tiny objects | A 6-pixel object inside a drawn box is mostly background; a point is exact |
| Defect location on industrial imagery | Position matters, the size is measured elsewhere |

<Warning>
Point accuracy is zoom-dependent. For dense scenes like shelf labels, zoom to 150-200 percent before clicking; a marker that is five pixels off on a tiny tag is a labeling error a reviewer will send back.
</Warning>

## Frequently asked questions

<AccordionGroup>
  <Accordion title="Can a single object carry multiple points?">
    Yes. Points are independent annotations, so skeleton-style labeling (several named keypoints on one object) works by using one class per keypoint type, or attributes to distinguish them.
  </Accordion>
  <Accordion title="How do points export?">
    As x and y coordinates with class and metadata, alongside your other annotation types. See <a href="/guides/essentials/exports">Exports</a> for format details.
  </Accordion>
  <Accordion title="What is the fastest way to place many points of different classes?">
    Work class by class: arm one hotkey, sweep the whole image for that class, then switch. Class-switching per object costs more time than a second pass.
  </Accordion>
</AccordionGroup>
